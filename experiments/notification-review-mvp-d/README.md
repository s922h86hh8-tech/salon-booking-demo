# MVP-D｜通知結果不明・店舗管理画面（独立・架空データのみ）

作成日：2026年11月12日  
位置付け：**通知が届いたか分からない場合の店舗向け操作性・安全上の案内を検証する独立画面。実LINE、実予約、実顧客、実送信なし。**

## 開発目的

v0.67では、送信処理の結果が不明となった通知を`OUTCOME_UNKNOWN`のまま保留し、**自動再送しない**ローカルSQLiteの独立技術検証が成功した。

その次の不足項目は、店舗側が結果不明の通知を一覧にし、保留理由・対象予約・同意・履歴・確認できない点を見ながら、判断内容を記録できる画面だった。MVP-Dはこれを**データを外部送信しない単体Webページ**として試作した。

## 新規ファイル

- `experiments/notification-review-mvp-d/index.html`：架空の結果不明一覧・明細・操作履歴・判断パネル
- `experiments/notification-review-mvp-d/style.css`：iPhone幅を想定したシンプルなレスポンシブUI
- `experiments/notification-review-mvp-d/model.js`：v0.67の状態語を参照した、架空データ専用の独立状態モデル
- `experiments/notification-review-mvp-d/app.js`：模擬案件の表示・絞り込み・判断・戻す・初期化
- `tests/notification-review-mvp-d.test.mjs`：状態モデルと操作画面の19件の自動テスト

## 画面で検証できること

1. **保留案件の一覧**：`OUTCOME_UNKNOWN`だけを初期表示。判断済みやすべての案件への絞り込みも可能。
2. **確認画面**：架空のお客様、対象予約、架空の予約日時・有効/変更済みの状態、配信目的別同意、試行回数・期限・結果不明となった時刻・模擬処理ID・保留理由を表示。
3. **操作履歴**：架空の予定登録、処理開始、結果不明、同意撤回、予約変更、判断結果の履歴を順に表示。
4. **模擬判断**：`MOCK_ACCEPTED`（架空の受付済みとの判断）または`MOCK_NOT_ACCEPTED`（架空の未受付との判断）を選ぶ。必ず「この試作は実LINEの配信証拠ではない」と確認してから記録。模擬受付済みなら再送しない。
5. **模擬再試行の承認**：模擬未受付の場合に限り、同意・有効な元予約・期限・回数のサンプル条件が合えば「再試行の模擬承認」という状態へ。**実際の再送はしない**。
6. **危険な状態は停止**：同意が停止している、元予約が変更済み、期限切れ・上限超過などは、模擬再試行を許可しない。
7. **操作履歴の保持**：判断後も保留から結果への記録を表示。判断済み案件の二重確定や結果の反転を画面モデル側で拒否。
8. **初期化**：「架空データを初期状態に戻す」で元の4つの架空案件へ戻す。ブラウザ再読み込みでも同様。

## セキュリティと機能の境界

- **MVP-Dの画面内データは架空の4件**。**v0.67のSQLiteと連動しない。** サーバー認証、通信、DB保存、LINE Messaging API、実予約操作、実送信、料金処理はすべて未実装。
- GitHub Pagesで閲覧できる場合も、**公開画面が安全なスタッフ用管理画面になるわけではない**。公開デモに本人の実情報やLINEのアクセストークンを入力しない。
- `connect-src 'none'`のCSPを指定し、画面処理から外部のネットワーク、ブラウザ永続保存、実顧客への送信を行わない。案内文や架空の予約表示は、HTML文字列を直接挿入せず`textContent`を使って表示する。
- 画面でチェックする同意・予約状態・期限・回数は**固定した架空モデルに対する表示上の判定**。本番のリアルタイム予約確認や本人確認を行った証拠ではない。
- `MOCK_ACCEPTED`と`MOCK_NOT_ACCEPTED`は、ユーザーが画面上で選ぶ模擬判断であり、外部事業者の受付結果を検証するものではない。
- 複数端末間での同期、操作担当者の本物の本人確認と権限、証拠の保存、改ざん防止、同意撤回反映時間、障害復旧、バックアップ、外部送信の厳密な一回保証は未実装。
- 架空の時刻表示には`Asia/Tokyo`を指定しているが、サンプルのUTC固定日時の表示を変換しているだけ。店舗ごとのタイムゾーンや営業日設定を実用化したものではない。
- 本試作での「模擬再試行の承認」は、その場で配信キューのジョブを再開する操作ではない。ユーザーに無断で再送しないという設計を見せるための状態遷移。
