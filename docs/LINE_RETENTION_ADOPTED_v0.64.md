採用の由来：ユーザーが参考動画の機能を見た上で追加を承認したこと。実装は既存の正本・正式版と独立して進める。

## 1. 採用範囲

1. LINEを入口として、店舗専用ページで予約・予約変更・取消を行う。
2. 予約前日などに、本人が希望する連絡先へリマインドを提案・送信する。
3. 来店周期に応じて、希望者へ適切なタイミングで次回予約候補を提案する。
4. キャンセル枠に適合するキャンセル待ち希望者へ安全に案内する。
5. 各導線を予約・来店・会計・経営分析へ接続し、案内数だけでなく実来店・限界利益・作業時間を測定する。

**「LINEを使える」だけでは差別化にならない。** 新規予約・再来店・空き枠の追加回収・スタッフ対応時間の削減を、混同せずに計測して改善できることを重視する。

## 4. 本番で必須となるデータと安全策

- **店舗IDと顧客IDを分離した認証・認可**：メッセージ上の表示名・LINEの自己申告だけで予約所有権を証明しない。顧客が自店の予約を安全に確認・変更・取消できること。
- **同意の証跡**：目的別に、同意の内容、取得方法、日時、店舗、停止と再同意の履歴を記録。店舗側の操作で本人同意を勝手に作らない。
- **通知台帳**：`store_id`、`customer_id`、`booking_id`（該当時）、通知タイプ、予定時刻、下書き・承認・送信状態、配信停止、重複排除キー、再試行回数、配信コスト・配信プロバイダー応答を保持（個人情報は必要最小限）。
- **二重送信・取り消し後の誤配信防止**：承認時・送信直前・予約確定時に、本人同意・対象予約・送信頻度・有効期限・残予算を再検証。成功後のリトライでは二重配信しない。
- **キャンセル枠**：複数候補へ同時に「確定予約できる」と告げない。提示の有効期限、短時間の仮確保（将来検証）、予約確定時の排他、競合・辞退時の再案内方法を規定する。無断の予約確定は行わない。
- **本番費用**：LINE側のプラン・送信通数・追加費用は、実装段階で公式の最新条件を確認。月額や1通単価を固定的に埋め込まない。
- **公開・課金・実送信の承認**：画像・キャンペーン文面・配信対象・予算を店舗オーナーが確認してから送る。無断で広告出稿・案内配信しない。

## 5. 分析項目（事実と推定の線引き）

| 指標 | 計測方法の目標 | 検証上の注意 |
|---|---|---|
| 案内対象人数・配信数・配信費用 | 配信プロバイダー応答と通知台帳 | 模擬送信は実送信に含めない |
| URLからの予約 | 予約IDと通知固有IDを紐づけ、確定まで追跡 | クリックは予約・来店ではない |
| 再来店件数 | 過去の予約・来店・会計の連続性 | 単に新しい予約だけでは再来店とは言えない |
| キャンセル枠回収件数 | 取消→案内→空き枠に新しい予約→実来店を照合 | 案内がなかった場合でも枠が埋まった可能性を区別 |
| 限界利益 | 実会計から追加変動費等を差し引く | 売上＝利益ではない |
| 省力化時間 | 導入前後に同じ作業を測る | 時間価値と現金の人件費削減を区別 |
| 純増効果 | 実績比較や適切な対照期間・対照群の検討 | 配信経由予約すべてを「増加分」とみなさない |

## 6. 次の優先工程

- **P0**：実際の顧客・店舗認証、通知同意、配信停止の証跡、通知台帳、送信重複防止、予約枠の排他・変更取消連動を、外部送信なしのローカル独立試験で固める。

- **P3**：配信実績と予約・実来店・会計を連結し、月間の増分限界利益・作業時間・システム料金・配信費用を可視化する。
