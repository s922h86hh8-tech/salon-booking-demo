## 1. 何を変えるか

デモを「機能の見本を並べたサイト」から、「お店の1日の仕事が迷わず流れる体験」に変える。合言葉は **「見ればわかる。触れば進む。」** とする（仮）。

**デザインの前提**
- **予約表が最初に開く主画面**。スタッフが縦軸・時間が横軸の15分刻みのまま。iPhoneでは横スクロールとスタッフ名の固定を継続。
- 情報の表示は「①次の操作 → ②重要な数字・予約情報 → ③詳細」。操作に関係しない長い説明は初期表示で畳む。
- 文言は短く。ただし**仮受付と予約確定、模擬会計記録と実際の決済完了、支払い差額と現金実査差額**を混同しない。
- 同じ予約を画面ごとに入力し直さず、予約→お客様情報→会計→レジ集計へ移動できるようにする。現状に存在しない顧客マスター、永続データやリアル決済を実装済みと表現しない。
- 開発中は**架空データ・ブラウザ内メモリのみ**、外部通信禁止のCSP維持。本番DB・顧客・決済・LINE・Google・HPB接続はしない。

| **会計** | 選択中の架空予約、コース、請求額、支払い合計と差額 | 割引、支払い方法別金額、会計操作担当、模擬レシート履歴 | 主役の金額を分かりやすく並べる。予約表から直接開く |
| **レジ** | 開店状態、あるはずの現金、前回数えた現金、現金の差額 | 金種入力、開店・何度でも中締め・再計数・閉店、返金・両替・入出金と履歴 | v0.41の階層表示を整理し、操作に必要な部分を優先 |
| **集計**（今後の検証候補） | 模擬売上合計、現金／非現金、未会計件数 | コース・予約経路・スタッフ別などの架空集計 | 現行の会計履歴・レジ集計から段階的に新設。高度な分析を実装済みと表現しない |
| **店舗設定** | 店舗・スタッフ・コース・ベッド | 連携の案内、操作ガイド、名称の設定、デモの初期化 | 設定と説明を一か所に整理。連携は案内だけ |

**別扱いで維持する機能**：
- 「担当未定」は現行の予約表の最下段で受付順に並べる。**空き枠回収（キャンセル待ち）とは別物**として維持する。
- キャンセル枠回収は予約画面の補助機能へ整理するが、通知・承諾は引き続き架空のまま。
- **お客様向け予約画面は店舗管理画面とは別**。他のお客様情報・スタッフ休憩・店舗内部の詳細は見せない。管理画面切替は本当の認証ではないことを示す。
- カウンセリング・施術記録・お客様マスターは**将来の設計領域**。健康情報の収集は認証、権限、同意、保管・削除方針の決定後に検討する。

## 3. 主画面：予約表

表示の優先順（案）：
1. 店舗名・デモ日付・管理メニュー（コンパクト）。
2. 「今日の予約」の見出しと **予約件数／担当未定／会計待ち** など、実際に計算できる状態数値（新設する場合は架空デモと明示）。
3. 最上段のよく使うコース、スタッフ名を左に固定した15分刻み予約表。予約・準備・休憩・空き・担当未定を区別。
4. 確定予約枠：「時刻」「ほぐし60分｜お客様A」「予約経路の仮マーク」。お客様名の操作で予約詳細（お客様、コース、担当、ベッド、予約経路）を開く。
5. 予約枠から「会計へ」「時間調整」などを**文脈に合う場所に表示**。画面幅が狭ければ詳細パネル・モーダルにまとめる。ドラッグ位置計算と確認ダイアログは維持。

**プライバシー**：公開デモは架空名だけ。将来の本番でも、予約表の一覧に健康情報・細かなカウンセリング結果を直書きしない。

## 4. 会計・レジの情報階層

**会計の3ステップ**
1. **予約を選ぶ**：コース、担当と元の価格を確認。
2. **割引を選ぶ**：値引き券は割引、商品券は支払い方法として区別。
3. **支払いを入力**：請求額、支払い合計、差額を明確に表示。複数手段の合計が合うときだけ確認を経て**模擬会計を記録**。

**レジの3段階**
1. **開店金を登録**（金種と確認者）
2. **現金を確認**（必要に応じ中締め・再計数・出入金）
3. **閉店を確認**（最終実査と差額の履歴）

レジの大きな数値は「あるはずの現金」「前回数えた現金」「現金の差額」。前回実査の値を**現在の実査値のように誤認させない**。決済方法の内訳・金種詳細・履歴はタップで表示。

## 5. 短いフレーズ・表示ルール

| 意味 | 表示する語（案） | 注意 |
|---|---|---|
| 日々の主画面 | 今日の予約 | 架空日付を明示 |
| 新しい予約 | 予約を入れる | 確定前に内容確認 |
| 担当者が決まっていない状態 | 担当未定（仮受付） | 確定予約ではない |
| 結果の確認 | 予約を確定 | 重複確認を省略しない |
| 会計開始 | 会計へ | 対象予約を引き継ぐ |
| 割引設定 | 割引を選ぶ | 商品券と混同しない |
| 決済入力 | 支払いを入力 | 現在は模擬決済 |
| レジのシステム計算値 | あるはずの現金 | 予測残高であり実査ではない |
| 現金を数えた記録 | 前回数えた現金 | 計測時点を併記する設計候補 |
| 現金照合 | 現金の差額 | 前回実査・予定現金との差 |
| 時間調整 | 時間を変更 | コース料金は勝手に変更しない |

「お客様の連絡先」「禁忌・健康情報」のような機微情報は、簡略化を理由に予約表で常時表示しない。

## 6. 操作・見た目のルール

- スマホの主要ボタンは押しやすい大きさ（目安44px程度以上）、項目間に適切な余白。コンパクトな予約表は文字を省略できるが、タップして全文を確認できる。
- タップ／ドラッグは確認画面を経て確定。横スクロールとドラッグ位置の一致はv0.36で利用者が実機検証した動作を維持。
- 予約枠・休憩・準備・担当未定・未会計などは色に加えて短いラベルでも区別。色だけに依存しない。
- デモ画面には「架空データ」「実予約・実決済なし」を邪魔にならない場所に常時表示。入力画面で実顧客の個人情報を受け付けない。
- メニューと重要な操作はなるべく少なくする。ただし完全に機能を削るのでなく、必要な場所に整理して移す。
