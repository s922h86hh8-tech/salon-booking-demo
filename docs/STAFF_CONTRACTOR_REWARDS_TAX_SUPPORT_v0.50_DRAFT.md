# 店舗向けAI予約・会計・経営管理システム
## 業務委託セラピスト・報酬管理・確定申告準備 設計案 v0.50-DRAFT

作成日：2026-11-01（日本時間）
状態：**仕様提案・未実装**。正本「引継ぎマスター v1.0」に従う。デモ正式版v0.36、最新の全体検証版v0.49は**一切変更しない**。
対象：リラクゼーション店舗向けの既存リポジトリ `s922h86hh8-tech/salon-booking-demo`。他プロジェクトへ共有しない。

### 目的
店舗オーナーが「誰に、どの施術・売上を根拠として、何円の業務委託報酬を支払い、いつ支払ったか」を説明できる。
業務委託セラピストは「月ごとの報酬明細、年間の収入記録、未払・支払済みを含む一覧」を確認・CSV/PDF出力し、自分で帳簿や確定申告資料に利用できる。
**確定申告書自体の税額計算・作成完了・税務署提出・e-Tax直接送信を実装済みとは言わない。** 本番化に当たっては税務専門家による制度確認が必要。

### 0. 最重要：契約上のお金の流れを2つに分ける
同じ「店頭10,000円／セラピスト取り分60%」でも契約・請求主体によって会計処理は違う。

| 事業モデル（例） | 店舗会計の役割 | セラピスト側に必要な整理 |
|---|---|---|
| **店舗売上＋業務委託報酬** | 店舗がお客様に販売した売上を計上、セラピストに委託報酬を支払う | 原則としてその契約に沿った役務の報酬売上・請求書・受取／未収記録 |
| **セラピスト売上＋場所代・手数料** | 店舗は場所代・媒介手数料・代理受領等を契約に従い記帳 | セラピスト本人の対お客様売上と、店舗へ支払う場所代・手数料の分離 |

実際の税務上の区分は契約・請求主体・取引実態・税区分に依存するため、この二つを混同しない。スタッフ画面で契約モデルの明示を必須とする設計。雇用契約（給与）も別系統とし、名称だけで業務委託だと決めつけない。

### 1. スタッフ登録：雇用形態と契約ルール
- 共通：セラピスト名／所属・稼働開始日・終了日／対応コース／予約表の表示名／有効・休止。
- 契約種別：業務委託、雇用、オーナー本人等（報酬計算エンジンを共用する前提にはしない）。
- 業務委託：上記の契約モデル、契約開始日・終了日、契約条件の版、締め日、支払期日、支払方法、税区分・インボイス登録状態（必要な範囲）。**マイナンバー・本人確認書類・銀行口座は公開デモには入力しない**。
- 報酬の計算基準：①施術売上に一定％、②コース別固定額、③コース別％、④指名等の追加報酬、⑤個別の例外の組合せを想定。
- ％の適用対象：通常料金／割引後の請求額／クーポンの店舗負担区分／指名料等の対象可否／税抜・税込を**契約ごとに明示**。決済方法手数料などは一律に差し引かない。
- 計算端数処理：「各施術単位」「月締め時」の別と切捨て・切上げ・四捨五入などを契約で指定。
- 契約改定は過去へ遡って勝手に適用しない。有効開始日・終了日と契約版を施術・会計ごとに固定（スナップショット）。

### 2. 支払対象の確定
- 予約確定だけでは報酬の対象にしない。「施術完了確認」と「会計記録」を区別し、**どの条件で報酬が発生するか**を契約で定義。
- 取消・無断キャンセル・当日キャンセル料・施術途中終了・返金・再施術・報酬訂正は区別。
- 1件ごとに施術ID、予約ID、会計ID、施術担当スタッフID、契約版、コース、日時、通常料金、割引、課税区分、取り分、調整理由を参照。
- 会計担当と施術担当は現行デモですでに分かれている。**会計担当を業務委託の施術報酬対象と取り違えない**。
- 同じ施術・会計で二重計算しない。訂正は差分・返金／追加計算の行を追加し、過去明細を黙って上書きしない。

### 3. 報酬計算の例（デモ値。契約が「割引後×60%」と明示されている場合のみ）
通常料金5,000円／店舗負担割引1,000円 → 対象金額4,000円。
**委託報酬 4,000円×60%＝2,400円**（税区分・端数・指名料・諸手数料・源泉徴収の要否はこの例では未設定）。
「通常料金×60%」なら3,000円となるため、料率だけ保存するのは不十分。

### 4. 月別の締め・支払
業務委託スタッフごとに以下の画面を作る（全てデモ段階では架空の情報）：
- 当月の対象施術件数／対象売上／歩合・固定の委託報酬／加算・減算／報酬合計
- 締め日／確定日／支払期日／支払方法／振込予定額／実際の支払日／未払い
- 未確定・確定・支払予定・一部支払・支払済み・要確認
- 店舗が確定した月次明細をセラピストへ提示する。「異議・差額」確認導線を別途設計
- 支払期日が迫った／超過した場合は**共通異常管理（v0.46以降）**へ通知候補
- 支払記録は現金レジ・実振込・モック決済を混同しない。実振込APIは未実装

### 5. 年別集計：確定申告の準備
**セラピスト本人用**：
- 1月〜12月の月別報酬一覧（支払確定と実受取を別列）
- 施術日別明細、委託報酬・調整・返金・未払、振込日、支払元
- 契約モデルに応じて、店舗の委託報酬が収入なのか、対お客様売上と場所代が必要なのかを分ける
- 支払明細・請求書・適格請求書など、関係する書類と紐づく保管情報（実ファイル・添付保存は後工程）
- 年間合計CSV、月別明細CSV、印刷／PDF明細を設計対象とする
- 交通費・家賃・消耗品など**本人が他で負担した必要経費は自動では分からない**。経費入力／会計ソフト連携は別工程
- 所得区分、税額、確定申告義務・控除等はこのシステムが決定しない

**店舗管理者用**：
- セラピスト別の業務委託報酬台帳、計上・確定・支払と残額
- 月別・年別の実施施術売上、委託報酬、店舗側収益（契約モデルごと）
- 支払調書の対象か、源泉徴収の要否があるかは**該当業務・資格・支払者の属性により個別の法的判定が必要**。全委託セラピストへ一律源泉徴収したり「支払調書発行が必要」とは扱わない
- 適格請求書等の保存、消費税区分、登録番号の取扱いなどは制度に従う
- 実店舗側の課税仕入れ控除可否は契約モデル・インボイス状況・税制の条件を踏まえて確認

### 5.1. 2026年のフリーランス取引・支払に関する注意
- 2026年11月1日時点の公正取引委員会の2026年版案内では、対象となる業務委託で、取引条件（業務内容、報酬額、支払期日等）を書面または電磁的方法により明示することや、原則として給付受領日から60日以内のできる限り短い期間内で具体的な支払期日を定めるルールが示されている。システム上も**契約発注日／役務提供日／報酬額／約定支払日**を別々に保存する。
- 同じ2026年版案内では、**2026年1月1日以降に業務委託する対象取引の振込手数料を、従前の合意を理由に委託先負担として報酬から差し引くこと**について、報酬の減額に当たる旨が案内されている。したがって「振込手数料を毎回スタッフ報酬から自動控除する」設定は初期仕様に入れない。制度の適用対象・取引日・例外を法律専門家と確認する。出典：https://www.jftc.go.jp/freelancelaw_2026/
- **締め日と支払期日は同一ではない**。月末締めを選んでも支払期限の適法性を自動保証しないため、設定時に要確認アラートを設ける案とする。

### 5.2. 申告用の年次集計に必要な日付
- 予約日、施術完了日、会計記録日、報酬が確定した日、請求日、支払日、入金確認日を混同しない。年間明細には**取引日ベースと入金日ベース**の両方を出せるようにする。
- どの年の所得として計上するかは所得区分・会計方式等に依存するため「受取額の年合計＝確定申告の収入」と断定しない。税理士などによる確認前の金額には「参考集計」と明示する。

### 6. 権限・閲覧・修正履歴
- 店舗管理者：全店舗の契約・報酬・支払閲覧（必要な権限を付与された者のみ）。
- セラピスト本人：**自分の業務委託報酬・明細・支払履歴だけ**。他のスタッフの報酬・店舗全体の営業秘密は見せない。
- 報酬比率などの契約条件変更と報酬確定・支払記録は権限・承認を要求。本人確認された操作者、作業日時、変更前後、理由を監査ログに保存（本番機能）。
- v0.49の「操作履歴」は**画面内メモリの表示例**なので、本物の報酬管理には不十分。認証・改ざん対策・バックアップ・永続DBが必要。
- CSV/PDFに銀行情報・個人番号などを不必要に出さない。公開デモには実名・電話・口座・個人番号を入力しない。

### 7. 管理画面案（「見ればわかる。触れば進む。」）
```

 ├ スタッフ管理

 │   ├ 契約（業務委託・雇用ほか）

 ├ ベッド・設備
 └ 営業日・勤務

店舗の経営管理（管理者）
 ├ 今日・今月の売上
 ├ 業務委託の報酬管理
 │   ├ 要確認／未確定
 │   ├ 月次締め・支払予定・支払済み
 │   └ 支払明細・年別集計
 └ 予約／会計／レジ／操作履歴

セラピスト本人専用（本番の権限が必要）
 ├ 今月の報酬
 ├ 支払明細
 ├ 支払履歴
 └ 年間集計・CSV
```
長い税務説明は通常画面に並べず「詳しく見る」「帳簿用の出力」で確認できるようにする。

### 8. v0.49からの必要なデータ追加
現行の模擬会計レコードは `bookingId, serviceStaff(名前), cashier(名前), menuName, full, discounts, due, amounts, recordedAt` を持つ。**スタッフとコースの永続的な識別子・契約版・税区分・報酬基準・施術完了・明細確定・支払日がない**。
将来の報酬計算では `staffId` と `menuId`、売上・会計・施術の個別ID、契約ID・契約版・計算スナップショットが必要。
既存デモは日付別に画面メモリを持つので、**スタッフやコースのマスター、契約ルールは全日共通**とし、予約や施術・会計の取引履歴は日付別に管理、報酬台帳は期間を横断して作る。

### 10. 法令の確認と限界（2026-11-01時点に確認した一次資料）
- 国税庁 No.2070・2080：青色・白色申告とも帳簿や証拠書類の保存が必要。 https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/2070.htm および https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/2080.htm
- 国税庁 No.1350・2210：事業所得・必要経費は売上と経費を区別して算定。 https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/1350.htm および https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/2210.htm
- 国税庁 No.6497・6498：仕入税額控除のための帳簿・請求書等・インボイス条件。 https://www.nta.go.jp/taxes/shiraberu/taxanswer/shohi/6497.htm および https://www.nta.go.jp/taxes/shiraberu/taxanswer/shohi/6498.htm
- 国税庁 No.2792・2793・7431：源泉徴収や支払調書の対象となる報酬・支払者・提出範囲は限定されており、一律に全業務委託報酬へ適用してはならない。 https://www.nta.go.jp/taxes/shiraberu/taxanswer/gensen/2792.htm ・ https://www.nta.go.jp/taxes/shiraberu/taxanswer/gensen/2793.htm ・ https://www.nta.go.jp/taxes/shiraberu/taxanswer/hotei/7431.htm
- 公正取引委員会（2026年フリーランス法）：取引条件の書面等による明示、報酬金額・支払期日の明確化と支払いルールが重要。適用条件の個別確認が必要。 https://www.jftc.go.jp/freelancelaw_2026/
- 厚生労働省：契約名が「業務委託」でも、実態により労働者として扱われ得る。 https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/koyou_roudou/koyoukintou/zaitaku/index_00002.html
