## できるようになったこと（すべて架空データ）

ローカルAPIが同じSQLite台帳の予約を読む・更新する。二つの異なる模擬利用者トークンで接続したときも同じ状態を参照でき、同じ枠の競合を拒否する。申込、取消、再予約、予約表取得、監査一覧を区別する。

| 操作 | ローカルAPI |
|---|---|
| 空き照会 | `GET /v0.62/stores/{storeId}/availability?date=YYYY-MM-DD&menuId=...&staffId=...&bedId=...&startMinute=...` |
| 予約確定 | `POST /v0.62/stores/{storeId}/bookings` |
| 予約一覧 | `GET /v0.62/stores/{storeId}/bookings?date=YYYY-MM-DD` |
| 予約取消 | `POST /v0.62/stores/{storeId}/bookings/{bookingId}/cancel` |
| 模擬監査一覧 | `GET /v0.62/stores/{storeId}/booking-audit` |

予約経路（`source`）と認知経路（`discovery`）を分離。お客様側の申込みは`source=website`に固定し、任意の店舗経路を名乗らせない。スタッフ側のみ所定の手入力経路を登録できる。ただし**この本人区別は実際の認証ではない**。

## 利用制限・セキュリティ境界

- `createLocalBookingApi({fictionalTestOnly:true,...})`という明示条件がない限り起動しない。
- ローカルIP`127.0.0.1`へのバインドのみ。インターネット公開はしない。ブラウザOrigin／Cookieを拒否し、CORS許可を付けない。
- 模擬利用者は**テスト内で乱数生成したトークン**から、テストプロセスのメモリ内対応表によって識別する。パスワード、MFA、パスキー、セッション失効などの実装はない。トークンや実個人情報をGitHubに置かない。
- 権限情報・店舗・予約IDはHTTPボディから信用せず、サーバー側の確定値で固定する。ボディの不明フィールドは拒否する。
- JSONのみ、本文は最大16KiB、URL・クエリーの検証、非キャッシュ、内部SQLエラーの非公開。
- 予約重複はv0.61の`BEGIN IMMEDIATE`と最新予約の再照会＋既存`Core.canBook`で判定。既存の予約は上書きせず、取消履歴は追記。
- **この構成はインターネット上の実予約・個人情報処理に必要なセキュリティを備えていない。公開・外部接続・実情報投入は禁止。**

## 検証結果

2026-11-08 GitHub Actions `42488992177` にて、**174件中174件合格、失敗0件**。従来の162件とv0.62の新規12件。

検証対象：
- localhost限定の起動
- 異なる模擬利用者が共通の予約台帳を参照
- 同一枠への二つのHTTP申込み：一方は確定（201）、一方は競合（409）
- 二重送信の冪等処理、同じキーを別内容で再送した場合の拒否
- 本人以外の取消、別店舗アクセス、停止スタッフの拒否
- 取消後の空き復活と再予約
- 電話などの模擬スタッフ手入力、予約経路の固定
- 担当者・店舗・予約IDの偽装フィールド拒否
- 不正JSON・大きすぎる本文・未知の項目・不正クエリー・Origin付き要求・不許可メソッド拒否
- 監査保存に失敗した際の予約未確定・内部SQL情報の非開示
- 監査イベントの日時と発生順の維持

v0.61には、**独立したWorkerスレッド二つが同じSQLiteファイルを取り合う実行試験**もあり、同時アクセスでも1件のみ確定したことを検証している。v0.62の二つのHTTPリクエストはローカルサーバープロセス上の統合試験であって、インターネット上の異なる端末による実機試験ではない。

## まだ不足する工程

1. **予約変更・日付移動の原子的処理**（変更失敗時は元予約が残る／二重実行しない）。
2. **実際のお客様の予約本人確認**、店舗のログイン、権限、セッション保護、予約の取得・変更・取消の安全な本人証明。
3. **予約ページと管理画面の分離と接続**。MVP-Aのページ内状態を公開サーバーや実店舗データにそのまま接続しない。
4. 実用DBの選定・運用、予約設定変更・定休日・スタッフ休暇、バックアップ、データ移行、監査改ざん防止、同時処理の負荷・障害試験。
5. 通知と同意、キャンセル待ちの安全な案内、顧客データの最小化・削除・保存期間、Google/SNS/HPB等の利用規約確認。
6. iPhone Safariからの実機操作と見やすさ、戻る・再試行・エラー表示。
7. 集客ホームページの独立公開、予約経路ごとの実来店／会計／粗利益の測定、AI告知案の人間による承認。
